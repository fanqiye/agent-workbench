# 本机操作

服务监听 8805，默认模型服务为 11434。日志在 `runtime/server.log` 与 `runtime/server-error.log`。`local.ps1 stop` 只停止本项目进程，保留数据；下次启动会把未完成调查标记为需要人工核对。

| 现象 | 判断与处理 |
| --- | --- |
| 第二个操作进程启动被拒绝 | 同一运行目录只能有一个服务/CLI 操作进程。先停止服务，或为独立实验使用 `--state` 新目录 |
| 模型超时或预算耗尽 | 查看工具记录和错误；不要把 review 当完成。用新任务重做，不手改状态为完成 |
| 查询被拒绝 | 检查是否只读 sales、是否用了允许函数、是否聚合到 50 行以内。不能为演示关闭授权器 |
| 草稿数字与表格不同 | 以 compare_revenue 的元单位计算表为准，核对 SQL 与原 CSV；模型解释不自动发布 |
| 引用失效 | 身份撤回、权限或版本改变后重新检索，不能复用旧结果 |
| 规划反复失败 | 检查可用窗口和截止时间是否可满足。没有合法时段时转人工，不延长截止时间冒充成功 |
| 日历无法批准 | 输入是否已变更、任务是否全部覆盖、是否仍有冲突；重新规划 |
| 旧导出文件不同 | 保留现有文件人工检查。系统拒绝覆盖，不强行修补已被手动修改的日历 |

备份前停止本项目服务与 CLI，复制整个私有 runtime。数据库、文档库、分析库、配置与日程输入应作为一组保管；不在运行中复制单个 sqlite 文件。没有自动恢复到线上账户的动作，恢复后仍需核对已有导出文件。

日历确认操作只写本机文件。相同任务重复确认返回原文件记录；崩溃留下不完整文件时拒绝覆盖。不要把文件幂等性宣称为日历服务的端到端 exactly-once。
